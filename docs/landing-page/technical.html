01 / Get started

Add Necto to ASP.NET Core

The current package targets .NET 10. Start with an ASP.NET Core application that has AddOpenApi() configured. Install the package:

Terminal
dotnet add package Necto.OpenApi
Program.cs · complete setup
using Necto;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddOpenApi();
var app = builder.Build();

// Register your endpoints here.

if (app.Environment.IsDevelopment())
{
    app.MapOpenApi();
    app.MapNectoEndpointMappings();
    app.UseNectoUI();
}

app.Run();

Run the app and open /necto/. The compiled Vue frontend is embedded in the .NET assembly. Consumers do not need Node.js, pnpm, or a separate frontend deployment.

Already using another OpenAPI route? Pass it to app.UseNectoUI(openApiPath: "/your/openapi.json"). A single generated Necto mappings route is discovered automatically.

The gallery shows the current development version. Published NuGet releases may have an earlier UI. Run the samples from the repository to try the latest changes.

02 / Follow the values

Connections come from metadata

  1. DescribeOpenAPI supplies operations, request fields, schemas and responses.
  2. ConnectA Roslyn source generator emits response-to-request value mappings during compilation.
  3. ExploreThe UI resolves those mappings against OpenAPI and offers related requests.

The generator matches compatible fields by dedicated CLR identifier types, supported scalar field names, or explicit [EndpointValue("…")] keys. For example, Invoice.Id can supply invoiceId; Invoice.Reference can match reference or invoiceReference.

Automatic generation currently supports Minimal API registrations with a constant .WithName("…") in the same fluent chain. Nested objects and arrays are supported. Other integrations can publish explicit mappings; the FastEndpoints sample demonstrates this.

Selecting an object fills matching request inputs. You can edit the values before sending. Related GET/HEAD requests with valid inputs can be sent directly; write operations open in the editor.

Mappings identify compatible values. They do not infer business rules or guarantee that an operation will succeed. Custom JSON converters are opaque to the generator.

Save a flow. Use fresh responses.

Saved requests keep inputs for one endpoint. Presets supply shared values across requests. Scenarios store a chain and its response-to-request bindings.

  • Replay runs sequentially and reads mapped values from each new response.
  • Inspect step results and the source of transferred values.
  • Review and explicitly run workflows that include write operations.

Array selections are positional: reordering can select a different object. Missing fields, HTTP errors or network failures stop later steps. Saved configurations live in browser storage; run results stay in workspace memory.

A bounded preview for large responses

Preview renders arrays and objects in local pages of 25 entries. Changing a Preview page does not call the API or change its pagination parameters. Search examines the whole parsed response and can reveal an object outside the current page.

  • Large JSON is parsed in a background worker.
  • Long strings and raw text also have bounded page sizes.
  • Download saves the complete original response, not just the visible page.

The full response and parsed JSON still occupy browser memory. Local pagination bounds rendering, not download size or memory consumption. Performance depends on payload shape, device and browser.

Two views of the connections

Entity graph: inspect models described by OpenAPI and the operations associated with them. Endpoint graph: explore response-to-request mappings between operations. Select a node, inspect its connections, and open its request.

Graphs complement the request workspace. They describe the metadata available to Necto, rather than observing runtime service traffic.

Connect another API

Add an OpenAPI document and its Necto mappings in Settings. Each API keeps its own identity and request URLs. Explicit API-scoped mappings allow values to flow between configured services.

For services on another origin, configure CORS to allow the Necto page to fetch metadata and make requests. Sharing browser presets with an external API is an explicit opt-in.

Bring your own agent through MCP

The optional MCP bridge shares the visible API catalog, types and relationships with an agent you connect. You can queue a prompt in Necto and view progress and results reported by that agent.

The agent needs its own model, HTTP tools and API credentials. Necto supplies metadata and task coordination; the bridge does not execute arbitrary HTTP requests or start an agent on its own.

app.MapNectoAgent();
app.UseNectoUI(agentPath: "/necto/agent");

Host it with your API

The quick start enables Necto in Development. If you expose the UI or MCP bridge elsewhere, configure access through the host application's authentication and endpoint policies. Browser request behavior remains subject to the API's authorization and CORS rules.

Both samples are available in the repository. Building Necto itself requires the .NET SDK, Node.js and pnpm; using the published package does not require a frontend toolchain.
